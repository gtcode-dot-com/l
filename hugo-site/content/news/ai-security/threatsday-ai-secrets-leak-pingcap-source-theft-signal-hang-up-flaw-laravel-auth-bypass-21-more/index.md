8. Critical API authentication bypass

   [Laravel Patches Critical TokenGuard Flaw Allowing API Authentication Bypass](https://github.com/laravel/framework/security/advisories/GHSA-f9x3-7vq9-cph6)

   Laravel has patched a critical security flaw (CVE-2026-114509, CVSS score: 9.2) that could allow its built-in TokenGuard to be bypassed to authenticate as an arbitrary existing user without knowledge of their valid API token. "Under certain database configurations (MySQL/MariaDB), an attacker can submit a specially crafted, non-string credential value that is mishandled during the authentication lookup, causing the underlying query to match an unintended user record rather than failing authentication as expected," Laravel
   [said](https://github.com/laravel/framework/security/advisories/GHSA-f9x3-7vq9-cph6)
   . "An unauthenticated attacker may authenticate as another user without possessing that user's API token, leading to authentication bypass and account takeover on any route protected by the affected guard." The issue has been patched in versions 13.29.0 and 12.68.0.

When a bad actor prompts ChatGPT for a deployment review of their repository, it encounters the hidden instructions and proceeds to write a GitHub Actions workflow into another, private repository that has a ChatGPT connector with the default All-repositories grant. The workflow then accesses secrets and other sensitive information, and exfiltrates it to the attacker. According to security researcher Sunil Tripathy, the vulnerability stems from a combination of indirect prompt injection, an overprivileged ChatGPT connector, and the ability of GitHub Actions to automatically run arbitrary code when the agent makes a commit to the private repository. "It demonstrates cross-account write operations, CI execution and secret exfiltration via the ChatGPT GitHub connector specifically, using indirect prompt injection from a public repository with zero attacker access to the victim," Tripathy
    [said](https://sunilawesome.in/chatgpt-github-connector-vulnerability)
    . "The attack requires no command injection and no document upload — just a public repository and a victim who asks their agent to review it." Following responsible disclosure to OpenAI, the company described the issue as out-of-scope.
